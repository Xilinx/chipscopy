JTAG¶

Cable options such as the TCK clock frequency are read and written through Cable. Low-level TAP shift sequences are built with JtagSequence.

Warning

Cable options are hw_server state shared by every connected client, and they persist for the life of the hw_server process. A change made by one session is visible to every other session and survives session close. Always restore the original value.

Changing an option is not synchronized with other traffic on the cable. The caller is responsible for not retuning a cable while it is in active use elsewhere, for example a live ILA capture or a PDI program.

frequency is quantized to what the cable hardware can generate, and frequency_list is advisory only at this level: hw_server accepts values outside the list and snaps them to the nearest achievable rate rather than rejecting them. Vivado’s set_property PARAM.FREQUENCY <hz> [current_hw_target] reaches the same underlying option, but the two surfaces are not interchangeable. Vivado models PARAM.FREQUENCY as an enum whose members are the frequency_list values, so it validates against the list where hw_server does not, and it caches the value it requested rather than rereading it, so a value read back through ChipScoPy can disagree with what Vivado reports for the same cable.

Reaching a cable¶

An ordinary session with no cs_server_url is the cheapest safe recipe:

from chipscopy import create_session

session = create_session(hw_server_url="TCP:my-host:3121")
cable = session.cables.get(Serial="252502174339A")

original = cable.get_option("frequency")
try:
    cable.set_option("frequency", 3_000_000)
    ...  # slow the clock for a marginal-signal experiment
finally:
    cable.set_option("frequency", original)

Do not reach for initial_device_scan=False as an optimization. It saves very little, and it skips the cable-readiness wait, because wait_for_all_cables_ready is only called from Session.scan_devices.

Specifies the dict used for filtering cables in the session.

Filters the QueryList returned by Session.cables. Both the raw hw_server property names (Description, Serial) and lowercase aliases (description, serial) are accepted. name is always the cable’s human readable description, matching Cable.name.

get_option(key)[source]¶

Reads a cable option value from the hw_server.

Option values are read live from the hw_server on every call. They are not cached in the api layer. Supported keys are cable dependent. frequency (in Hz), frequency_list, skew and timing_class are common.

Cable options are hw_server state shared by every client, and they persist for the life of the hw_server process. Restore anything you change.

Examples:

cable = session.cables.get(Serial="252502174339A")
original = cable.get_option("frequency")
try:
    cable.set_option("frequency", 3_000_000)
    ...
finally:
    cable.set_option("frequency", original)

key (str) – Name of the option, for example "frequency".

set_option(key, value)[source]¶

Sets a cable option in the hw_server and returns the value actually applied.

The hw_server is free to apply a value different from the one requested. JTAG TCK frequency in particular is quantized to what the cable hardware can generate. On the FT4232H cables this was verified against, an out-of-range value was snapped down to an achievable one rather than rejected, but that is cable-dependent and another cable may reject the request instead. This method sets the option, reads it back, and returns the read-back value. It does not raise when the applied value differs from the requested value, so the caller must compare.

The returned value is a best-effort read-back. The set and the read are two independent unlocked requests, so another client may have intervened.

A frequency of 0 is reserved. On some cables it requests auto-negotiation rather than setting a rate, and on others it does nothing. Read the value back.

Parameters:

  • key (str) – Name of the option, for example "frequency".

  • value (Any) – New value for the option. Only int values are supported today.

Return type:

Any

Returns:

The option value as read back from the hw_server after the set.

Raises:

  • NotImplementedError – If this cable type does not support options.

  • TypeError – If value is not an int.

  • Exception – If the hw_server rejects the set or the read back.
